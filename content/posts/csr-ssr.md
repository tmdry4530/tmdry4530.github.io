# CSR / SSR 특징


## CSR (Client Side Rendering)


클라이언트 측에서 페이지를 렌더링 하는 방식이다. 사용자가 웹사이트에 접속하면 서버는 html파일 대신 js파일을 보내고, 이 파일은 웹사이트의 모든 로직과 렌더링을 담당하며 사용자의 브라우저에서 실행된다

- 초기 로딩시간이 길지만, 이후 페이지 이동은 빠르다
- 서버부하가 적다
- SEO(검색엔진)에 불리하다

## SSR (Server Side Rendering)


서버 측에서 페이지를 렌더링 하는 방식이다. 사용자가 웹사이트에 접속하면 서버는 미리 렌더링된 html파일을 보내고, 이 파일은 이미 웹사이트의 모든 내용을 담고 있으므로 사용자는 페이지를 빠르게 볼수있다.

- 초기 로딩시간이 빠르다
- 서버부하가 크다
- SEO에 유리하다.

# 두 방식의 차이점


### 초기 로딩 시간

- CSR : 클라이언트에서 모든 js를 다운로드하고 실행해야 하므로 초기 로딩시간이 길어지고, js가 모두 로드되고 실행된 후에야 사용자에게 페이지가 보여지기 때문이다
- SSR : 서버에서 html을 렌더링하고 이를 클라이언트에게 전송하므로, 사용자는 js가 로드되기를 기다리지 않고 빠르게 페이지를 볼수있다.

### 서버 부하

- CSR : 클라이언트가 대부분의 렌더링 작업을 처리하므로 서버부하가 적다. 서버는 주로 정적파일을 제공하는 역할을 한다.
- SSR : 서버가 각 요청마다 새로운 html을 생성하므로 서버 부하가 크다.

### SEO

- CSR : 검색엔진 크롤러가 js를 실행하지 않는 경우, 렌더링 되지 않은 초기 상태의 페이지를 크롤링하게 되므로 SEO에 불리하다.
- SSR : 서버에서 렌더링된 완전한 페이지를 제공하므로, 검색 엔진 크롤러가 페이지의 전체 내용을 크롤링 할수있어 SEO에 유리하다.
