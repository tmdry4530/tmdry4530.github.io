#

### 1. 브라우저 렌더링 과정

1. **HTML 파싱**: 브라우저는 HTML 문서를 읽고 파싱하여 DOM(Document Object Model) 트리를 만듭니다. DOM 트리는 문서의 구조를 나타냅니다.

2. **CSS 파싱**: 브라우저는 CSS 파일을 읽고 파싱하여 CSSOM(CSS Object Model) 트리를 만듭니다. CSSOM 트리는 스타일 정보를 포함합니다.

3. **렌더 트리 생성**: 브라우저는 DOM 트리와 CSSOM 트리를 결합하여 렌더 트리를 만듭니다. 렌더 트리는 페이지의 시각적 표현을 나타냅니다.

4. **레이아웃**: 브라우저는 렌더 트리의 각 요소를 화면에 배치합니다.

5. **페인팅**: 브라우저는 렌더 트리의 각 요소를 화면에 그립니다.

### 2. HTTP, HTTPS 통신 방식 차이

- **HTTP**: 일반 텍스트로 데이터를 전송하는 비보안 프로토콜입니다.
- **HTTPS**: SSL/TLS 암호화를 사용하여 데이터를 전송하는 보안 프로토콜입니다. HTTPS는 HTTP보다 안전하며 민감한 정보(예: 비밀번호, 신용 카드 정보)를 보호하는 데 사용됩니다.

### 3. OOP 설명

객체 지향 프로그래밍(OOP)은 객체라는 개념을 중심으로 구성된 프로그래밍 패러다임입니다. 객체는 데이터(속성)와 동작(메서드)을 캡슐화합니다. OOP의 주요 개념은 다음과 같습니다.

- **객체**: 데이터와 동작을 캡슐화하는 기본 단위입니다.
- **클래스**: 객체를 만드는 템플릿입니다.
- **상속**: 클래스가 다른 클래스의 속성과 메서드를 상속받을 수 있습니다.
- **다형성**: 객체가 여러 가지 형태로 존재할 수 있습니다.
- **캡슐화**: 객체의 내부 데이터와 동작을 외부로부터 숨기는 것을 의미합니다.

### 4. 함수형 프로그래밍이란?

함수형 프로그래밍은 함수를 중심으로 구성된 프로그래밍 패러다임입니다. 함수형 프로그래밍에서는 함수를 일급 객체로 취급하며, 함수를 다른 함수에 전달하거나 함수에서 반환할 수 있습니다. 또한, 함수형 프로그래밍은 부작용을 최소화하고 순수 함수를 사용하는 것을 강조합니다.

### 5. 순수 함수란?

순수 함수는 다음 조건을 만족하는 함수입니다.

- **동일한 입력에 대해 항상 동일한 출력을 반환합니다.**
- **부작용이 없습니다.** (예: 외부 상태 변경, 데이터베이스 액세스 등)

### 6. OOP와 함수형 프로그래밍의 가장 큰 차이점

OOP는 객체와 클래스를 중심으로 구성되며, 상태와 동작을 캡슐화하는 것을 강조합니다. 반면, 함수형 프로그래밍은 함수를 중심으로 구성되며, 부작용을 최소화하고 순수 함수를 사용하는 것을 강조합니다.

### 7. 웹 프로토콜이란?

웹 프로토콜은 웹에서 통신하는 데 사용되는 규칙 집합입니다. 일반적인 웹 프로토콜에는 HTTP, HTTPS, TCP/IP, DNS 등이 있습니다.

### 8. HTTP 통신이란?

HTTP(Hypertext Transfer Protocol)는 웹 브라우저와 웹 서버 간에 통신하는 데 사용되는 프로토콜입니다. HTTP는 클라이언트-서버 모델을 기반으로 하며, 클라이언트(웹 브라우저)가 서버에 요청을 보내고 서버가 응답을 반환합니다.

### 9. HTTP 1.1과 2.0의 차이

- **HTTP 1.1**: 각 요청에 대해 새로운 TCP 연결을 설정합니다.
- **HTTP 2.0**: 하나의 TCP 연결을 사용하여 여러 요청을 동시에 처리할 수 있습니다. 이는 HTTP 2.0이 HTTP 1.1보다 더 빠르고 효율적임을 의미합니다.

### 10. AJAX 뭐임?

AJAX(Asynchronous JavaScript and XML)는 웹 페이지를 새로 고침하지 않고 서버와 비동기적으로 통신하는 기술입니다. AJAX는 웹 페이지의 일부만 업데이트할 수 있으므로 사용자 경험을 향상시킬 수 있습니다.

### 11. Promise와 Callback의 차이점과 각각의 장단점

- **Callback**: 함수를 다른 함수에 인수로 전달하여 비동기 작업이 완료되면 호출되는 함수입니다. 콜백은 중첩 콜백(콜백 지옥) 문제가 발생할 수 있습니다.
- **Promise**: 비동기 작업의 결과를 나타내는 객체입니다. Promise는 콜백 지옥 문제를 해결하고 비동기 코드를 더 쉽게 작성할 수 있도록 합니다.

### 12. Promise란 뭐고? 코드가 어떻게 구성되어 있냐?

Promise는 비동기 작업의 결과를 나타내는 객체입니다. Promise는 다음과 같은 상태를 가질 수 있습니다.

- **Pending**: 작업이 진행 중입니다.
- **Fulfilled**: 작업이 성공적으로 완료되었습니다.
- **Rejected**: 작업이 실패했습니다.

Promise는 `then()` 메서드를 사용하여 작업이 완료되면 실행할 콜백 함수를 등록할 수 있습니다. 또한, `catch()` 메서드를 사용하여 작업이 실패했을 때 실행할 콜백 함수를 등록할 수 있습니다.

### 13. Async, Await가 뭐냐? 사용한 경험 있음?

Async/await는 Promise를 기반으로 한 비동기 코드를 더 쉽게 작성할 수 있도록 하는 키워드입니다. `async` 키워드는 함수를 비동기 함수로 만들고, `await` 키워드는 Promise가 해결될 때까지 기다립니다.

### 14. Async, Await, Promise 차이

- **Promise**: 비동기 작업의 결과를 나타내는 객체입니다.
- **Async/await**: Promise를 기반으로 한 비동기 코드를 더 쉽게 작성할 수 있도록 하는 키워드입니다.

Async/await는 Promise를 사용하여 비동기 코드를 작성하는 더 간편한 방법입니다.

### 15. 자바스크립트 데이터 타입

자바스크립트에는 다음과 같은 데이터 타입이 있습니다.

- **원시 타입**: 숫자(Number), 문자열(String), 불리언(Boolean), null, undefined, 심볼(Symbol), BigInt
- **참조 타입**: 객체(Object), 배열(Array), 함수(Function)

### 16. 자바스크립트에서 NumberType은 다른 언어들과 차이점은 뭐냐? 왜 하나만 있냐?

자바스크립트의 Number 타입은 정수와 부동 소수점 숫자를 모두 나타낼 수 있습니다. 다른 언어에서는 정수와 부동 소수점 숫자를 나타내는 별도의 타입이 있는 경우가 많습니다. 자바스크립트는 단일 Number 타입을 사용하여 코드를 단순화하고 메모리 효율성을 높입니다.

### 17. 자바스크립트 원시 타입은 몇 개냐? 종류는?

자바스크립트에는 7개의 원시 타입이 있습니다.

- 숫자(Number)
- 문자열(String)
- 불리언(Boolean)
- null
- undefined
- 심볼(Symbol)
- BigInt

### 18. 실행 컨텍스트 설명

실행 컨텍스트는 자바스크립트 코드가 실행되는 환경입니다. 실행 컨텍스트에는 코드 실행에 필요한 모든 정보가 포함됩니다. 실행 컨텍스트는 전역 컨텍스트, 함수 컨텍스트, eval 컨텍스트 등이 있습니다.

### 19. 자바스크립트의 호이스팅 뭐냐? 어떻게 이루어져 있음?

호이스팅은 자바스크립트 코드에서 변수와 함수 선언이 코드의 맨 위로 옮겨지는 것처럼 동작하는 현상입니다. 실제로 코드가 옮겨지는 것은 아니지만, 자바스크립트 엔진이 코드를 실행하기 전에 변수와 함수 선언을 먼저 처리하기 때문에 이러한 현상이 발생합니다.

### 20. 클로저 뭐냐? 왜 사용함? 클로저를 만들 때 선호하는 패턴은?

클로저는 함수가 자신이 생성된 외부 범위의 변수에 액세스할 수 있는 함수입니다. 클로저는 다음과 같은 경우에 사용됩니다.

- **상태 유지**: 클로저는 외부 범위의 변수 값을 유지할 수 있습니다.
- **콜백 함수**: 클로저는 콜백 함수로 사용되어 비동기 작업이 완료되면 외부 범위의 변수에 액세스할 수 있습니다.

클로저를 만들 때 선호하는 패턴은 즉시 실행 함수(IIFE)를 사용하는 것입니다.

### 21. 가비지 컬렉터가 뭐냐?

가비지 컬렉터는 더 이상 사용되지 않는 메모리를 자동으로 해제하는 프로그램입니다. 자바스크립트와 같은 언어에서는 가비지 컬렉터가 자동으로 메모리를 관리하므로 개발자가 수동으로 메모리를 해제할 필요가 없습니다.

### 22. 자바스크립트의 순환 참조란? 어떤 게 문제이고 해결 방법은?

순환 참조는 두 개 이상의 객체가 서로를 참조하는 경우입니다. 순환 참조는 가비지 컬렉터가 메모리를 해제하지 못하게 하여 메모리 누수를 발생시킬 수 있습니다. 순환 참조를 해결하는 방법은 참조를 끊거나 약한 참조를 사용하는 것입니다.

### 23. 자바스크립트의 배열이 실제 자료구조 배열이 아닌데 그 이유는?

자바스크립트의 배열은 실제 자료구조 배열이 아니라 객체입니다. 이는 자바스크립트 배열이 동적으로 크기를 조정할 수 있고 다양한 데이터 타입을 저장할 수 있도록 하기 위한 설계 결정입니다.

### 24. 이벤트 루프에 대하여 지껄여 봐라. 동시성 모델에 대해서 설명

이벤트 루프는 자바스크립트 엔진이 이벤트를 처리하는 메커니즘입니다. 이벤트 루프는 큐에 이벤트를 저장하고 이벤트가 발생하면 큐에서 이벤트를 꺼내 처리합니다. 자바스크립트는 단일 스레드이지만 이벤트 루프를 사용하여 동시성을 구현합니다.

### 25. 프로토타입이란?

프로토타입은 객체가 상속받는 속성과 메서드를 정의하는 객체입니다. 자바스크립트는 프로토타입 기반 상속을 사용합니다.

### 26. 자바스크립트에서 this가 뭐냐? 몇 가지로 추론되냐?

`this`는 자바스크립트에서 함수가 호출되는 방식에 따라 달라지는 키워드입니다. `this`는 다음과 같은 규칙에 따라 추론됩니다.

- **전역 컨텍스트**: 전역 컨텍스트에서 `this`는 전역 객체를 참조합니다.
- **함수 컨텍스트**: 함수 컨텍스트에서 `this`는 함수를 호출한 객체를 참조합니다.
- **객체 메서드**: 객체 메서드에서 `this`는 메서드가 속한 객체를 참조합니다.
- **생성자 함수**: 생성자 함수에서 `this`는 새로 생성된 객체를 참조합니다.

### 27. 일반 함수의 this와 애로우 함수 this는 어떻게 다르냐?

일반 함수의 `this`는 함수가 호출되는 방식에 따라 달라지지만, 애로우 함수의 `this`는 함수가 정의된 범위의 `this`를 상속받습니다.

### 28. call, Apply, bind 함수가 뭐냐?

`call()`, `apply()`, `bind()` 함수는 함수의 `this` 값을 변경하는 데 사용됩니다.

- **call()**: 함수를 호출하고 `this` 값을 설정합니다.
- **apply()**: 함수를 호출하고 `this` 값을 설정하며, 인수를 배열로 전달합니다.
- **bind()**: 함수의 `this` 값을 설정하여 새로운 함수를 반환합니다.

### 29. useStrict 모드에서의 this는 뭐냐?

`use strict` 모드에서 전역 컨텍스트의 `this`는 `undefined`입니다.

### 30. ES6 크롬 브라우저를 제외하곤 ES6 스펙에 대한 지원이 완벽하지 않다. 해결 방안은?

ES6 스펙을 지원하지 않는 브라우저에서 ES6 코드를 실행하기 위해 Babel과 같은 트랜스파일러를 사용할 수 있습니다.

### 31. Babel이 뭐냐?

Babel은 ES6 코드를 이전 버전의 자바스크립트 코드로 변환하는 트랜스파일러입니다.

### 32. ES6에서 추가된 스펙에 대해 아는 대로 말해봐라

ES6에서는 다음과 같은 스펙이 추가되었습니다.

- **let, const**: 블록 범위 변수 선언
- **화살표 함수**: 간결한 함수 표현식
- **클래스**: 클래스 기반 상속
- **모듈**: 코드 모듈화
- **Promise**: 비동기 작업 처리
- **async/await**: 비동기 코드 작성 간소화
- **템플릿 문자열**: 문자열 삽입 간소화
- **구조 분해 할당**: 객체 및 배열에서 값 추출 간소화
- **Spread 연산자**: 배열 및 객체 요소 분해
- **Rest 매개변수**: 가변 인수 처리

### 33. var, let, const의 차이점은? (function Scope, block Scope의 개념에서)

- **var**: 함수 범위 또는 전역 범위 변수를 선언합니다.
- **let**: 블록 범위 변수를 선언합니다.
- **const**: 블록 범위 상수를 선언합니다.

### 34. class가 뭐냐? prototype, function의 ES5 스펙으로 class 구현 쌉가능함?

`class`는 ES6에서 도입된 클래스 기반 상속을 위한 키워드입니다. ES5에서는 `prototype` 및 `function`을 사용하여 클래스와 유사한 기능을 구현할 수 있지만, ES6 `class` 키워드만큼 간편하지는 않습니다.

### 35. 리액트 뭐냐?

리액트는 사용자 인터페이스를 구축하기 위한 자바스크립트 라이브러리입니다. 리액트는 컴포넌트 기반 아키텍처를 사용하며, 가상 DOM을 사용하여 효율적인 업데이트를 가능하게 합니다.

### 36. 리액트 상태 관리에 대해 알고 있냐? 리덕스 사용해 봤으면 설명해봐라.

리액트에서 상태 관리는 컴포넌트의 상태를 관리하는 것을 의미합니다. 리덕스는 리액트 애플리케이션의 상태 관리를 위한 라이브러리입니다. 리덕스는 단일 저장소(store)를 사용하여 애플리케이션의 모든 상태를 관리하며, 액션(action)을 통해 상태를 변경합니다.

### 37. 리액트 동작 원리

리액트는 가상 DOM을 사용하여 실제 DOM을 직접 조작하지 않고 효율적으로 업데이트합니다. 리액트 컴포넌트가 업데이트되면 리액트는 가상 DOM을 사용하여 변경 사항을 계산하고 실제 DOM에 필요한 최소한의 변경 사항만 적용합니다.

### 38. 컴포넌트가 뭐냐?

컴포넌트는 사용자 인터페이스의 일부를 나타내는 재사용 가능한 코드 조각입니다. 리액트 컴포넌트는 클래스 컴포넌트 또는 함수형 컴포넌트로 만들 수 있습니다.

### 39. 클래스 컴포넌트와 함수형 컴포넌트의 차이점?

- **클래스 컴포넌트**: 클래스를 사용하여 정의하며, 상태(state)와 라이프사이클 메서드를 가질 수 있습니다.
- **함수형 컴포넌트**: 함수를 사용하여 정의하며, 상태나 라이프사이클 메서드를 가질 수 없습니다. (Hooks 사용 가능)

### 40. Hook 뭐냐?

Hook은 함수형 컴포넌트에서 상태 및 라이프사이클 기능을 사용할 수 있도록 하는 함수입니다. 일반적인 Hook에는 `useState`, `useEffect` 등이 있습니다.

### 41. Redux-saga와 옵저버블 뭐냐?

- **Redux-saga**: 리덕스 애플리케이션에서 비동기 작업을 처리하기 위한 라이브러리입니다.
- **옵저버블**: 비동기 데이터 스트림을 처리하기 위한 패턴입니다.

### 42. 라이프사이클 메서드 종류?

리액트 컴포넌트에는 다음과 같은 라이프사이클 메서드가 있습니다.

- **생성**: `constructor`, `getDerivedStateFromProps`, `render`, `componentDidMount`
- **업데이트**: `getDerivedStateFromProps`, `shouldComponentUpdate`, `render`, `getSnapshotBeforeUpdate`, `componentDidUpdate`
- **제거**: `componentWillUnmount`

### 43. Angular, Vue, React 차이점?

Angular, Vue, React는 모두 사용자 인터페이스를 구축하기 위한 프레임워크 또는 라이브러리입니다. 주요 차이점은 다음과 같습니다.

- **Angular**: 완전한 프레임워크이며, 의존성 주입, 양방향 데이터 바인딩 등 다양한 기능을 제공합니다.
- **Vue**: 점진적으로 채택할 수 있는 프레임워크이며, Angular보다 가볍고 배우기 쉽습니다.
- **React**: 사용자 인터페이스 구축에 중점을 둔 라이브러리이며, 다른 프레임워크보다 유연합니다.

### 44. 타입스크립트 사용해 봤냐? 타입스크립트에 대한 본인의 생각과 장점은?

타입스크립트는 자바스크립트에 정적 타입 검사를 추가하는 언어입니다. 타입스크립트는 다음과 같은 장점이 있습니다.

- **타입 안전성**: 컴파일 시 타입 오류를 감지할 수 있습니다.
- **코드 가독성 향상**: 타입 정보를 통해 코드를 더 쉽게 이해할 수 있습니다.
- **IDE 지원 향상**: 타입 정보를 통해 IDE에서 더 나은 코드 완성 및 리팩토링 기능을 제공할 수 있습니다.

### 45. 라이브러리와 프레임워크의 차이점?

- **라이브러리**: 특정 작업을 수행하는 데 도움을 주는 코드 모음입니다. 개발자는 라이브러리를 사용하여 필요한 기능을 선택적으로 사용할 수 있습니다.
- **프레임워크**: 애플리케이션 개발을 위한 구조를 제공하는 코드 모음입니다. 프레임워크는 개발자가 따라야 하는 특정 규칙과 패턴을 정의합니다.

### 46. 두 명의 개발자가 있다? Git을 관리하는 방식은?

두 명 이상의 개발자가 Git을 관리하는 일반적인 방법은 다음과 같습니다.

- **중앙 저장소 사용**: GitHub, GitLab과 같은 중앙 저장소를 사용하여 코드를 공유하고 변경 사항을 관리합니다.
- **브랜치 사용**: 기능 개발, 버그 수정 등을 위해 브랜치를 사용합니다.
- **풀 리퀘스트 사용**: 변경 사항을 공유하고 검토하기 위해 풀 리퀘스트를 사용합니다.

### 47. 메서드 체이닝 뭐냐? 장단점?

메서드 체이닝은 객체 메서드를 연속적으로 호출하는 것을 의미합니다. 메서드 체이닝은 코드를 간결하게 만들 수 있지만, 디버깅이 어려워질 수 있습니다.

### 48. 메모라이제이션이란?

메모라이제이션은 함수 호출 결과를 캐시하여 동일한 입력에 대해 함수를 다시 실행하지 않고 캐시된 결과를 반환하는 기술입니다. 메모라이제이션은 함수 성능을 향상시킬 수 있습니다.

### 49. REST API가 뭐냐? 아는 대로 설명?

REST API는 웹 서비스를 구축하는 데 사용되는 아키텍처 스타일입니다. REST API는 HTTP 프로토콜을 사용하여 데이터를 주고받으며, GET, POST, PUT, DELETE와 같은 HTTP 메서드를 사용하여 CRUD 작업을 수행합니다.

### 50. CORS가 뭐냐? 왜 이러한 방법이 정의되었고 CORS와 관련해서 경험했던 이슈는?

CORS(Cross-Origin Resource Sharing)는 다른 도메인의 리소스에 액세스할 수 있도록 하는 메커니즘입니다. CORS는 웹 보안을 강화하기 위해 정의되었으며, 교차 출처 요청을 제한하여 악의적인 스크립트가 다른 도메인의 리소스에 액세스하는 것을 방지합니다.

### 51. ESLint, Prettier 써봄? 이게 뭐냐?

ESLint와 Prettier는 자바스크립트 코드 스타일을 검사하고 포맷하는 도구입니다. ESLint는 코드 품질을 향상시키고 코드 스타일을 일관되게 유지하는 데 도움을 주며, Prettier는 코드를 자동으로 포맷하여 가독성을 향상시킵니다.

### 52. 웹팩 뭐냐?

웹팩은 자바스크립트 애플리케이션을 위한 모듈 번들러입니다. 웹팩은 여러 개의 자바스크립트 파일과 의존성을 하나의 파일로 번들링하여 브라우저에서 로딩 속도를 향상시킬 수 있습니다.

### 53. 패키지 매니저로 어떤 거 사용함? npm, yarn은 어떻게 다르냐?

npm과 yarn은 자바스크립트 패키지를 관리하는 도구입니다. npm은 Node.js와 함께 제공되며, yarn은 Facebook에서 개발했습니다. yarn은 npm보다 빠르고 안정적인 것으로 알려져 있습니다.

### 54. 적응형과 반응형 차이?

- **적응형 웹 디자인**: 다양한 화면 크기에 맞게 레이아웃을 조정합니다.
- **반응형 웹 디자인**: 화면 크기에 따라 레이아웃을 유동적으로 변경합니다.

### 55. package.json의 역할은?

`package.json` 파일은 Node.js 프로젝트의 메타데이터와 의존성을 포함합니다. `package.json` 파일은 프로젝트 이름, 버전, 의존성, 스크립트 등을 정의합니다.

### 56. 프로세스와 스레드의 차이

- **프로세스**: 운영 체제에서 실행되는 프로그램의 인스턴스입니다. 프로세스는 독립적인 메모리 공간을 가지고 있습니다.
- **스레드**: 프로세스 내에서 실행되는 코드 실행 단위입니다. 스레드는 프로세스의 메모리 공간을 공유합니다.

### 57. CSR(클라이언트 사이드 렌더링), SSR(서버 사이드 렌더링)의 차이

- **CSR**: 브라우저에서 자바스크립트를 사용하여 페이지를 렌더링합니다.
- **SSR**: 서버에서 페이지를 렌더링하여 HTML을 브라우저에 전송합니다.

### 58. 이벤트 위임이란?

이벤트 위임은 이벤트 리스너를 부모 요소에 추가하여 자식 요소의 이벤트를 처리하는 기술입니다. 이벤트 위임은 성능을 향상시키고 코드를 간소화할 수 있습니다.

### 59. DOM을 건드리는 방식과 아닌 방식들의 차이는?

DOM을 직접 조작하는 방식은 성능이 저하될 수 있습니다. 리액트와 같은 라이브러리는 가상 DOM을 사용하여 DOM 조작을 최소화하고 성능을 향상시킵니다.

### 60. 반응형 프로그래밍이란?

반응형 프로그래밍은 데이터 스트림과 이벤트를 처리하는 프로그래밍 패러다임입니다. 반응형 프로그래밍은 비동기 데이터 처리를 간소화하고 코드를 더 쉽게 작성할 수 있도록 합니다.

### 61. 콜바이 밸류와 콜바이 레퍼런스(자바스크립트에서)

- **콜바이 밸류**: 값을 복사하여 함수에 전달합니다.
- **콜바이 레퍼런스**: 객체의 참조를 함수에 전달합니다.

### 62. 널과 언디파인드 차이

- **null**: 의도적으로 값이 없음을 나타냅니다.
- **undefined**: 변수가 선언되었지만 값이 할당되지 않았음을 나타냅니다.

### 63. inline과 inline-block 차이?

- **inline**: 요소가 한 줄에 표시되며, 너비와 높이를 설정할 수 없습니다.
- **inline-block**: 요소가 한 줄에 표시되지만, 너비와 높이를 설정할 수 있습니다.

### 64. virtual dom이란?

가상 DOM은 실제 DOM을 추상화한 개념입니다. 리액트와 같은 라이브러리는 가상 DOM을 사용하여 실제 DOM 조작을 최소화하고 성능을 향상시킵니다.

BST(Binary Search Tree)는 이진 트리 자료 구조의 일종으로, 왼쪽 하위 트리의 모든 노드 값이 루트 노드 값보다 작고 오른쪽 하위 트리의 모든 노드 값이 루트 노드 값보다 큽니다. BST는 효율적인 검색, 삽입, 삭제 작업을 제공합니다.

### 68. 동기와 비동기 처리 설명

- **동기 처리**: 작업이 완료될 때까지 코드 실행을 차단합니다.
- **비동기 처리**: 작업이 완료될 때까지 코드 실행을 차단하지 않고 다른 작업을 수행할 수 있습니다.

### 69. node.js 이벤트 큐 동작 원리

Node.js는 이벤트 루프와 콜백 큐를 사용하여 비동기 작업을 처리합니다. 비동기 작업이 완료되면 콜백 큐에 콜백 함수가 추가되고, 이벤트 루프는 콜백 큐에서 콜백 함수를 꺼내 실행합니다.

### 70. node.js 뭐냐? 어디에 사용하냐? 사용하는 이유는?

Node.js는 자바스크립트 런타임 환경입니다. Node.js는 서버 측 애플리케이션, 실시간 애플리케이션, API 등을 개발하는 데 사용됩니다. Node.js는 이벤트 기반 아키텍처를 사용하여 높은 성능과 확장성을 제공합니다.

### 71. node.js가 왜 싱글 스레드냐?

Node.js는 단일 스레드이지만 이벤트 루프를 사용하여 동시성을 구현합니다. 단일 스레드 모델은 메모리 관리를 단순화하고 성능을 향상시킵니다.

### 72. node.js 콜백은?

Node.js 콜백은 비동기 작업이 완료되면 호출되는 함수입니다. 콜백은 Node.js에서 비동기 작업을 처리하는 주요 메커니즘입니다.

### 73. node.js 모듈은 뭐냐

Node.js 모듈은 코드를 재사용 가능한 단위로 구성하는 방법입니다. Node.js는 CommonJS 모듈 시스템을 사용합니다.

### 74. 다른 백엔드 기술보다 node.js가 선호되는 이유는?

Node.js는 다음과 같은 이유로 다른 백엔드 기술보다 선호될 수 있습니다.

- **자바스크립트 사용**: 프론트엔드와 백엔드 모두에서 자바스크립트를 사용할 수 있습니다.
- **이벤트 기반 아키텍처**: 높은 성능과 확장성을 제공합니다.
- **풍부한 생태계**: 다양한 라이브러리와 프레임워크를 사용할 수 있습니다.

### 75. node.js와 함께 많이 사용되는 DB는 뭐냐

Node.js와 함께 많이 사용되는 데이터베이스는 MongoDB, MySQL, PostgreSQL 등이 있습니다.

### 76. node.js에서 가장 일반적으로 사용되는 라이브러리는?

Node.js에서 가장 일반적으로 사용되는 라이브러리는 Express, Socket.io, Lodash 등이 있습니다.

### 77. node.js의 장단점은?

- \*장점\*\*:
- 높은 성능 및 확장성
- 자바스크립트 사용
- 풍부한 생태계
- \*단점\*\*:
- 단일 스레드 모델
- 콜백 지옥 문제
- CPU 집약적인 작업에 적합하지 않음

### 78. 콜백 지옥 뭐냐?

콜백 지옥은 중첩된 콜백 함수로 인해 코드가 복잡하고 읽기 어려워지는 문제를 의미합니다. Promise와 async/await는 콜백 지옥 문제를 해결하는 데 도움을 줍니다.

### 79. API가 뭐냐? REST API 만들어 본 적 있음?

API(Application Programming Interface)는 다른 프로그램과 통신하는 데 사용되는 인터페이스입니다. REST API는 웹 서비스를 구축하는 데 사용되는 아키텍처 스타일입니다.

### 80. AWS와 같은 클라우드 서비스 알고 있냐? 사용해 봄?

AWS(Amazon Web Services)는 클라우드 컴퓨팅 서비스를 제공하는 플랫폼입니다. AWS는 서버, 스토리지, 데이터베이스, 네트워킹 등 다양한 서비스를 제공합니다.

### 81. GET, POST 알고 있냐?

GET과 POST는 HTTP 메서드입니다.

- **GET**: 서버에서 데이터를 가져오는 데 사용됩니다.
- **POST**: 서버에 데이터를 제출하는 데 사용됩니다.

### 82. 쿠키와 세션, 로컬 저장소의 차이점은?

- **쿠키**: 서버에서 클라이언트 브라우저에 저장되는 작은 데이터 조각입니다.
- **세션**: 서버 측에서 사용자 정보를 저장하는 메커니즘입니다.
- **로컬 저장소**: 브라우저에서 데이터를 저장하는 메커니즘입니다.

### 83. 크로스 브라우징이란?

크로스 브라우징은 웹 페이지가 다양한 브라우저에서 일관되게 표시되도록 하는 것을 의미합니다.

### 84. 문서 객체 모델이란?

DOM(Document Object Model)은 HTML 문서의 구조를 나타내는 프로그래밍 인터페이스입니다. DOM을 사용하여 HTML 요소를 액세스하고 조작할 수 있습니다.

### 85. 웹 접근성에 대하여 설명

웹 접근성은 장애인을 포함한 모든 사용자가 웹 사이트를 이용할 수 있도록 하는 것을 의미합니다. 웹 접근성을 고려하여 웹 사이트를 개발하면 더 많은 사용자가 웹 사이트를 이용할 수 있습니다.

### 86. 지역 변수와 전역 변수의 선언 방법과 차이점은?

- **지역 변수**: 함수 내부에서 `var`, `let`, `const` 키워드를 사용하여 선언합니다. 지역 변수는 함수 외부에서 액세스할 수 없습니다.
- **전역 변수**: 함수 외부에서 `var` 키워드를 사용하여 선언합니다. 전역 변수는 모든 코드에서 액세스할 수 있습니다.

### 87. RDBMS란 무엇이고 장단점은?

RDBMS(Relational Database Management System)는 관계형 데이터베이스를 관리하는 시스템입니다. RDBMS는 데이터를 테이블 형태로 저장하며, 데이터 무결성과 일관성을 보장합니다.

- \*장점\*\*:
- 데이터 무결성 및 일관성 보장
- 표준 SQL 언어 사용
- 다양한 데이터 관리 기능 제공
- \*단점\*\*:
- 확장성 제한
- 복잡한 쿼리 처리 성능 저하

### 88. JOIN이란(RDBMS)?

JOIN은 RDBMS에서 여러 테이블의 데이터를 결합하는 데 사용되는 SQL 연산입니다. JOIN은 데이터 관계를 기반으로 테이블을 연결하여 데이터를 검색합니다.

### 89. MySQL VS MongoDB

MySQL은 관계형 데이터베이스 관리 시스템(RDBMS)이고, MongoDB는 NoSQL 데이터베이스입니다. 주요 차이점은 다음과 같습니다.

- **데이터 모델**: MySQL은 관계형 데이터 모델을 사용하고, MongoDB는 문서 기반 데이터 모델을 사용합니다.
- **확장성**: MongoDB는 MySQL보다 확장성이 뛰어납니다.
- **데이터 무결성**: MySQL은 데이터 무결성을 보장하는 기능을 제공하지만, MongoDB는 데이터 무결성을 보장하지 않습니다.

### 90. React V6와 이전 버전의 차이점은?

React V6에는 다음과 같은 주요 변경 사항이 있습니다.

- **새로운 렌더링 엔진**: React V6는 새로운 렌더링 엔진을 사용하여 성능을 향상시킵니다.
- **자동 일괄 처리**: React V6는 더 많은 업데이트를 자동으로 일괄 처리하여 성능을 향상시킵니다.
- **새로운 API**: React V6에는 `useId`와 같은 새로운 Hook이 추가되었습니다.
- **IE 지원 중단**: React V6는 Internet Explorer를 지원하지 않습니다.
