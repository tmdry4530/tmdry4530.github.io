# ERC721 표준

- 대체 불가능 토큰 (NFT)은 외형적으로는 유사할 수 있지만, 각각 고유한 식별자를 가지고 있어서 서로 대체할 수 없다.

## ERC721의 특징

1. **고유성 :** 각 ERC721토큰은 고유한 식별자를 가지고 있어, 다른 토큰과 구별된다.
2. **소유권 :** 토큰의 소유자는 토큰을 전송하거나, 거래할 수 있는 권리를 가진다.
3. **프로그래밍 가능 :** 스마트 컨트랙트를 통해 다양한 기능과 규칙을 토큰에 적용할 수 있다.
4. **상호 운용성 :**  ERC721 표준을 준수하는 플랫폼 간에 토큰을 쉽게 전송하고 거래할 수 있다.

# 민팅이란?

- 블록체인 네트워크 상에서 새로운 토큰을 생성하는 과정
- 이 과정을 통해 각각의 NFT가 고유한 식별자와 메타데이터를 가지며 생성된다

## 민팅 과정

1. **메타데이터 준비 :** NFT가 대표할 아이템의 정보(이미지, 이름, 설명 등)를 메타데이터(JSON)형태로 준비한다.
2. **블록체인에 메타데이터 업로드 :** 준비된 메타데이터를 IPFS와 같은 분산 파일 시스템에 업로드하고, 해당 데이터의 주소(URL)을 얻는다.
3. **스마트 컨트랙트 호출 :** NFT를 생성하기 위해 스마트 컨트랙트의 민팅 함수를 호출하며, 이때 메타데이터의 주소를 인자로 전달한다.
4. **NFT 생성 :** 스마트 컨트랙트는 제공된 메타데이터 주소와 함께 새로운 NFT를 생성하고, 이를 요청한 사용자의 지갑 주소에 할당한다.

# IPFS를 활용한 NFT 메타데이터 저장 및 관리

- 중앙화된 저장소 대신, NFT 민팅에는 분산 파일 시스템인 IPFS를 사용한다.
- IPFS에 객체의 내용과 이미지를 업로드하면, 각 파일은 고유한 CID(콘텐츠 식별자)해시 URL을 통해 접근할 수 있다.
- IPFS는 중앙 서버 없이 여러 노드가 파일을 저장하는 분산 네트워크로, 높은 안정성을 제공한다.
- 파일은 무결성과 보안을 유지하며, 한 번 업로드되면 수정이나 삭제가 불가능하여 보관의 안정성을 보장한다.
- 수정이 필요한 경우, 새로운 버전의 파일을 업로드하고 새로운 CID를 받게된다.

# Opensea

- **ERC721 컨트랙트 배포 여부 확인 :** 트랜잭션의 input을 확인하여 앞자리가 `0x6080`이면 ERC721 배포로 간주한다. 이 경우, `to` 필드는 `null`이다.
- **트랜잭션 영수증 확인:** 영수증에서 `contract address`를 확인하여 CA 주소를 얻는다.

### ERC721 표준


NFT를 민팅하고, 각 NFT의 URI를 관리하는 기능을 제공한다.


```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "../../node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol";

contract chamNFT is ERC721 {
    constructor(string memory _name, string memory _symbol) ERC721(_name,_symbol){}

    mapping(uint256 tokenId => string tokenURI) _tokenURIs;

    uint256 totalSupply = 0;

    function minting(string memory tokenURI) public {
        _tokenURIs[totalSupply] = tokenURI;
        _mint(address(msg.sender), totalSupply);  
    } 

    function tokenURI(uint256 _tokenId) public view override returns(string memory){
        return _tokenURIs[_tokenId];
    }

    function _baseURI() internal view override returns (string memory){
        return "https://apricot-administrative-sparrow-942.mypinata.cloud/ipfs/";
    }

}
```

1. 오픈제플린에서 제공하는 ERC721 컨트랙트를 임포트한다.
2. ERC721을 상속하는 chamNFT 컨트랙트를 선언한다.
3. 생성자함수는 토큰의 이름과 심볼을 ERC721 부모 생성자에 전달해서 기본속성을 설정한다.

```solidity
mapping(uint256 tokenId => string tokenURI) _tokenURIs;

    uint256 totalSupply = 0;
```

1. 토큰의 고유 ID를 URI에 매핑한다. 이 URI는 NFT의 메타데이터를 저장하고있는 json파일의 위치를 가리킨다.
2. 현재까지 생성된 NFT의 총 수량을 추적한다. 초기값은 0이며 새로운 NFT가 생성될 떄 마다 값이 증가한다.

```solidity
function minting(string memory tokenURI) public {
        _tokenURIs[totalSupply] = tokenURI;
        _mint(address(msg.sender), totalSupply);  
    }
```

1. tokenURI라는 문자열 파라미터를 인자로 받는다
2. 이전에 매핑했던 _tokenURIs에 새로운 항목을 추가한다. 총 수량을 키로 사용하고 함수로 전달받은 tokenURI를 값으로 사용한다.
3. 새로운 NFT를 생성해서 함수를 호출한 주소에게 할당하고, totalSupply를 인자로 전달한다.

```solidity
function tokenURI(uint256 _tokenId) public view override returns(string memory){
        return _tokenURIs[_tokenId];
    }
```

1. 특정 토큰ID에 대한 URI를 문자열로 반환한다.
2. _tokenURIs에서 ID에 해당하는 값을 조회해서 반환한다. → 메타데이터 URI반환

```solidity
function _baseURI() internal view override returns (string memory){
        return "https://apricot-administrative-sparrow-942.mypinata.cloud/ipfs/";
    }
```

1. 함수는 문자열을 반환한다.
2. 함수가 호출될때마다 IPFS에 호스팅된 리소스를 가리키는 기본 URI를 반환한다.

### ERC721 토큰 판매 


ERC-721 토큰을 관리하기 위한 기능을 제공한다.


```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

import "../../node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol";

contract SaleNFT {
    ERC721 public _nft;


    constructor(address nft) {
        _nft = ERC721(nft);

    }
    function AccountGetAllNFT(address[] memory _ca) public {
        for (uint256 i = 0; i < _ca.length; i++) {
            ERC721 CA = ERC721(_ca[i]);
        }
    }

    function approveAll(address[] memory _mintCa) public {
        for (uint256 i = 0; i < _ca.length; i++) {
            ERC721 CA = ERC721(_ca[i]);
            CA.setApprovalForAll(msg.sender, true);
        }
    }
}
```

1. ERC721 토큰의 인스턴스를 저장한다.
2. nft의 주소를 인자로 받아, ERC721 인스턴스를 생성하고 _nft에 저장한다

```solidity

```

1. 컨트랙트주소의 배열을 인자로 받는다
2. 반복문을 통해 배열의 각 주소에 대해 해당 주소를 ERC721타입으로 변환하고 CA변수에 할당한다.

```solidity
function approveAll(address[] memory _mintCa) public {

            ERC721 CA = ERC721(_ca[i]);
            CA.setApprovalForAll(msg.sender, true);
        }
    }
```

1. 토큰의 컨트랙트 주소들의 배열을 인자로 받는다
2. 반복문을 통해 배열의 각 주소에 대해 해당 주소를 ERC721타입으로 변환하고 CA변수에 할당한다.
3. 함수를 호출한 주소가 해당 토큰 컨트랙트에서 모든 토큰에 대한 승인을 할수있도록한다.

### 화면 구현


파일을 선택해서 IPFS에 업로드하고, 파일의 해시를 사용해서 NFT발행


```javascript
import "./App.css";
import axios from "axios";
import { useState, useEffect } from "react";
import useWeb3 from "./hooks/web3.hook";
import abi from "./abi/chamNFT.json";

function App() {
  const [file, setFile] = useState(null);
  const { user, web3 } = useWeb3();
  const [nftContract, setNftcontract] = useState(null);
  useEffect(() => {
    if (web3 != null && nftContract == null) {
      const _nftContract = new web3.eth.Contract(
        abi,
        "0x632b26c81a5b13144fb137b7c8337fb05c39806b"
      );
      setNftcontract(_nftContract);
    }
  }, [web3]);
  const upload = async () => {
    const fileData = new FormData();
    fileData.append("file", file);
    const resp = await axios.post(
      "https://api.pinata.cloud/pinning/pinFileToIPFS",
      fileData,
      {
        headers: {
          "Content-Type": "multipart/form-data",
          pinata_api_key: "007a635df0ed0f4f191d",
          pinata_secret_api_key:
            "065ed2ccbc323721ab4d92414c958985721e56a71791e385c9fbb4ba960fa859",
        },
      }
    );

    const {
      data: { IpfsHash: urlhash },
    } = resp;
    console.log(urlhash);
    await nftContract.methods.minting(urlhash).send({
      from: user.account,
    });
    console.log(resp);
  };

  return (
    <div className="App">
      <label>IPFS에 파일 업로드</label>
      <input
        type="file"
        onChange={(e) => {
          setFile(e.target.files[0]);
        }}
      />
      <button onClick={upload}>파일 업로드</button>
    </div>
  );
}

export default App;
```
